# 2.7.8 发布说明

发布日期：2026-08-01

版本：`2.7.8`（Android `versionCode 53`）

本页只记录当前源码、数据库迁移、自动化测试和四端构建产物能够复现的结果。`2.7.6` 已由用户确认正常的小米 Dock 本版不修改。

## 本版修复

### 聊天记录与最新消息

- 新增按账号和会话隔离的持久化消息快照。再次进入私聊、群聊或聊天室时先显示本地快照，再按服务端游标增量校准，避免每次进入都从空白状态重新加载。
- 切换会话时同步重置快照请求状态，防止同一 Activity 复用后读取到上一会话或跳过新会话快照。
- 私聊、群聊和聊天室发送接口返回完整、已水合的消息对象；Android 发送成功后立即把消息合入当前列表并显示到最新位置，后台请求只负责最终一致性校准。
- 保留历史阅读锚点：普通增量刷新不会清空列表或强制把正在上翻的用户拉到底部。

### 通话消息卡片

- 语音和视频通话以发起方普通消息卡片写入聊天记录，不再另外生成冲突的系统级通话记录。
- 通话状态通过稳定 `call_id` 关联原消息；接通、挂断或失败后原位更新通话类型、状态与时长，例如“视频通话 · 通话时间：10分36秒”。
- 点击已结束的通话卡片可按上一次语音或视频类型重新发起通话。
- 服务端通话计时继续以真正接通时间为准，未接通不提前累计通话时长。

### 动态置顶与详情展示

- 个人动态空间使用显式页面模式，不再依赖 `user_id` 是否大于零来猜测当前页面，自己的动态空间同样可以稳定显示置顶区。
- 置顶动态显示在个人空间顶部，并且只有置顶项显示“置顶动态”；未置顶内容不显示“普通动态”标签。
- 公共动态保持普通时间线，不展示普通用户的置顶标识或置顶排序；单条详情保持沉浸式，不显示个人空间分区。

### 论坛回复与转发边界

- 论坛回复继续使用稳定 `root_comment_id` 归属主评论，并保留 `parent_id` 指向实际回复对象；新增主评论或列表顺序变化不会把回复移动到其他楼层。
- Android 评论树在根评论暂未分页加载时保留待归组回复，根评论到达后稳定合并，避免短暂串楼。
- 软件内转发严格区分群聊、聊天室和在线客服目标；选择在线客服时增加二次确认，避免把内容误发给客服会话。
- 服务端按真实 `room_kind` 复核目标类型，不能只依赖客户端标签。

## 数据库迁移

按 `backend/database/MIGRATION_ORDER.md` 顺序执行：

```text
backend/database/migrations/upgrade_20260801_call_message_cards.sql
```

迁移为通话与原消息增加稳定关联，并兼容已有通话记录。部署前必须备份数据库，执行后检查私聊、群聊和聊天室三种场景。

## 自动化验证

- `ChatMessageSnapshotStoreTest`、`ForumCommentThreadOrderTest`、`MomentDisplayPolicyTest` 通过。
- 用户端完整单元测试通过；平台总控、授权平台、管理员和用户四端 Java 编译通过。
- 五个改动控制器通过 PHP 语法检查。
- 四端 `2.7.8 (53)` debug 验证包完成构建，包名、包内版本、签名存在性、体积和 SHA-256 已由发布脚本逐项校验。

## 发布边界

- 当前四端仍是 debug 签名验证包，不冒充正式商用 release 包；固定生产签名和覆盖安装验证仍是发布阻断项。
- 通话双方音画、TURN、厂商后台权限、多人通话和弱网指标仍需真实服务与真机矩阵验收。
- 资金双重记账、三家地图原生 SDK、资源恶意文件隔离、实时 AI 检索和完整四级 RBAC/ABAC 不因本版专项修复而自动视为完成。
- 全部历史需求、推断补充、实施顺序和统一完成定义继续以[全量需求与实施总纲](../MASTER_REQUIREMENTS_AND_IMPLEMENTATION_PLAN.md)为准。
