## 唯一阻塞项：设备升级验收

本机已安装 Android Emulator 37.1.11、API 35 Google APIs x86_64 镜像并创建 `Yiyunying_API35` AVD，但固件虚拟化状态为关闭；Hypervisor Platform、Virtual Machine Platform 与 Hyper-V 未启用，`emulator-check accel` 返回不可用。软件加速启动也没有出现可连接的 ADB 设备。

当前证据边界：

- ADB 设备列表为空；
- 没有安装 code 61 RC 或 code 62 Stable APK；
- 没有执行 `adb install -r` 覆盖升级；
- 没有启动应用或验证登录、四角色入口、网络请求和更新后数据保留；
- 因此 `v2.8.0` 不能创建，pending manifest 不能 Finalize，官网不能切换正式下载。

解除阻塞只能采用以下任一路径：

1. 在 BIOS/UEFI 开启 CPU virtualization，重启 Windows，确认 `emulator-check accel` 和 `adb devices` 通过后再执行 RC → Stable 覆盖升级；或
2. 连接一台允许 ADB 调试的真实 Android 设备，先安装同角色 code 61 RC，再用 code 62 Stable `adb install -r`，启动并记录版本、签名连续、登录、网络和最小业务闭环。

仓库已提供 `android/tools/verify-device-upgrade.ps1` 作为唯一执行门禁：它严格绑定角色、serial、code 61 RC、code 62 Stable、production signer、v2 签名、非 debuggable、`install -r`、packageName/userId/dataDir 保留以及升级前后启动/前台验证；禁止 `-d` 和卸载。离线运行时合同 10/10 PASS，四角色真实 RC/Stable 已完成包与签名预检，并在无 ADB 设备时按预期 fail-closed，未安装 APK。设备就绪后需对 `user`、`admin`、`authorized`、`owner` 四角色分别执行：

```powershell
powershell -File android/tools/verify-device-upgrade.ps1 `
  -Role <user|admin|authorized|owner> `
  -Serial <adb-serial> `
  -RcApk <code61-rc-apk> `
  -StableApk <code62-stable-apk>
```
