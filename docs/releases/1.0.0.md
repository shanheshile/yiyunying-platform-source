## 为什么正式 1.0.0 使用 code65

- `versionName=1.0.0` 是客户看到的产品版本；`versionCode` 是 Android 判断覆盖安装和升级顺序的内部正整数，两者不要求数字一致。
- 已存在同正式包名、同 production signer 的内部 code62 制品。使用 code65 可以验证原地升级，也避免任何曾安装 code62、旧 code63 或旧 code64 候选的测试设备遭遇降级阻断。
- 使用 code1 会低于内部 code62，无法通过正常 `adb install -r` 覆盖升级；为追求数字一致而强制卸载会破坏 UID、dataDir 和本地数据连续性。
- 旧 code63、code64 候选来自较早源码 A，均已移出发布工作目录并保存在本机私有 superseded 目录；它们不能 Finalize、部署或公开。最新源码必须使用新的未复用 code65，不能覆盖或冒充旧候选。
- 后续正式补丁从 code66 继续单调递增，例如客户版本 `1.0.1` 可使用 code66。

## 设备升级门禁

正式门禁必须选择同一角色的两份 APK：

- 基线：隔离的 `2.8.0`、code62、非 Debug、production signer；
- 目标：已 Build 的 `1.0.0`、code65、非 Debug、同一 production signer。

`android/tools/verify-device-upgrade.ps1` 必须验证：

- 基线 code 小于目标 code65；
- 基线角色后缀正确，目标 `versionName` 精确为 `1.0.0-<role>`；
- 两端 packageName、production signer 和 v2 签名一致；
- 两端均为 `debuggable=false`；
- 只操作用户明确指定且唯一在线的 ADB serial；
- 使用 `install -r`，禁止 `-d` 和卸载；
- 升级前后 packageName、UID、dataDir 保持；
- 升级前后应用均能启动到前台；
- 另行记录登录、API 连通、关键业务入口和数据保留。

当前本机固件虚拟化关闭，AVD 无法进入 ADB，真实设备列表为空；1.0.0 APK 已 Build 但未安装，因此设备门禁仍为 **BLOCKED**。

## Debug 线上版迁移边界

线上 2.7.14 Debug 包名包含 `.debug`，1.0.0 正式包名不含 `.debug`，Android 会把它们视为不同应用。正式包不能冒充对 Debug 包的原地覆盖升级：

- 1.0.0 首发应通过官网提供独立安装；
- Debug 用户可重新登录恢复服务端账号和云端数据，但本地离线数据不会自动迁移；
- 在确认正式版登录与数据可见前，不应指导用户卸载 Debug 版；
- 不得直接把现有 Debug 更新策略指向正式 APK，否则可能因包名校验失败；
- 如需自动迁移，应另做 Debug 客户端迁移提示或受控导出/导入流程，并独立验收。

## 固定 Build、Finalize 与上线顺序

1. 完成至少一个角色的 code62 → code65 真实设备覆盖升级；正式对外前按既定要求扩展到四角色和目标真机矩阵。
2. 更新 release metadata、文档和设备证据，提交形成 B；精确 B 不预写。
3. 创建指向 B 的 annotated tag `v1.0.0`。
4. 从完全干净的 main/B 执行 Finalize，回读 manifest 的 A、B、tag、release identity 和 Git refs 一致。
5. 先备份并验证恢复点，再隐藏上传后端、数据库/私有资源和恰好四个 APK，复算服务器 hash、MIME、长度、Range/ETag。
6. 原子激活正式策略与官网，执行 HTTPS、健康、服务器、公网下载、生命周期和页面功能回读。
7. 推送 B 与标签，最后创建不覆盖历史的归档并做解压、逐文件哈希与 Git bundle 恢复演练。

任一步骤失败都应维持既有生命周期策略，官网继续显示“正式版尚未开放”，不得提前暴露 1.0.0 下载链接；不得重新开放已封堵的旧 Debug 公网直链。

## 完成定义

只有同时具备以下证据，才能称“1.0.0 已正式上线”：

- 新源码 A 和证据 B 已提交并推送；
- `v1.0.0` annotated tag 精确指向 B；
- finalized manifest 精确绑定 A、B、tag 和 production signer；
- 四端 code65 APK 完整审计通过；

- 生产备份、部署、策略和 HTTPS 健康通过；
- 官网与四个公网 APK 的 SHA-256、MIME、长度、Range/ETag 回读通过；
- 私有源码/history/delivery/project manifest 未进入公网；
- 新归档及恢复演练通过。
