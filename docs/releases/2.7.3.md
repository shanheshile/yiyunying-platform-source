# 2.7.3 发布说明与下一步开发目标

发布日期：2026-07-30

本页只记录可以由源码、测试或构建产物核验的事实。历史需求不因被写入路线图就自动视为完成；未形成客户端、服务端、数据库和真机闭环的内容统一列入“下一步开发目标”。

## 本版已完成

### 共享底部弹层

- 修复重复应用外观时，`MaterialButton` 已覆盖背景却继续调用 Shape API 导致的闪退。
- 共享按钮样式改由软件绘制的圆角 Ripple 背景负责，不再依赖容易被厂商系统覆盖的顶部/底部 inset。
- 增加重复应用样式的单元回归测试，覆盖自定义背景、触控反馈、最小尺寸与完整圆角。

**期望效果：** 更新、维护、收藏详情、确认发送等复用弹层不再因主题切换或二次渲染闪退，主按钮四角完整且不会被底部安全区裁切。

### 底部 Dock 兼容

- 用户端和管理端 Dock 统一关闭横向位移动画，避免选中项挤压其他入口。
- 固定显示图标和文字，收紧字号并增加可用高度与上下安全间距。
- 新增静态发布门禁，若 Dock 丢失文字模式、重新启用水平位移或高度低于兼容阈值，校验脚本直接失败。

**期望效果：** 小米、vivo 等不同系统上四个入口均显示图标与文字，选中态不跳动，底部不过度留白，也不被系统手势区遮挡。

### 版本与发布链路

- Android 四端、下载站包版本、发布元数据由同一版本脚本管理。
- 发布脚本核对四个 APK 的包名、`versionName`、`versionCode`、签名、大小和 SHA-256。
- 下载目录采用临时目录校验后原子切换；失败时恢复旧版本、旧元数据和旧下载目录。
- 禁止把 `127.0.0.1`、`localhost` 或模拟器地址写入公开下载元数据。
- 下载站测试要求恰好存在四端制品，文件名、版本、校验和和下载根路径全部合法。

**期望效果：** 源码版本、APK 内版本、更新接口和下载站显示保持一致，下载到的文件可追溯到同一次构建。

## 下一步开发目标

以下目标包含用户明确提出的需求，以及工程审查发现但用户未逐项描述的必要能力。它们是计划，不是本版完成声明。

### 1. 消息可靠性与离线浏览

**用户期望：** 私聊、群聊、聊天室、客服都能及时收发；向上查看历史时不被新消息拉到底部；断网仍能查看已缓存会话、资料、图片、视频、文件与转发快照。

**具体措施：**

- 建立统一消息状态机和本地账号隔离数据库，保存消息 ID、游标、幂等键、发送状态和本地删除状态。
- 以服务端递增游标同步，WebSocket 为主、增量 HTTP 为降级；修复空白会话必须先发消息才加载的问题。
- RecyclerView 使用稳定 ID、差量更新和滚动锚点；离底部时显示“新消息（N）”，由用户主动回到底部。
- 转发记录保存只读嵌套快照；匿名规则逐层生效，客服不可匿名，1/2/3 保留审计身份。

**验收标准：** 弱网不重复消息；历史位置不跳；断网可读；恢复网络后增量补齐；消息 P95 确认时间不高于 800 ms。

### 2. 通话、通知与后台运行

**用户期望：** 语音和视频点击后立即进入呼叫页，双方都有声音和画面，悬浮窗计时正确；来电只出现一个通知，支持接听/挂断，结束后三秒清理。

**具体措施：**

- 服务端维护呼叫状态机和事件序号，解决重复 offer/answer、单方挂断、占线和残留会话。
- TURN/STUN 健康检查、区域选择、弱网自适应和失败降级；摄像头固定合理默认焦段并按网络动态降清晰度。
- 明确本地预览镜像和发送画面的变换规则，大小窗交换使用可中断动画。
- 按 Android 规范实现单一高优先级来电通知、全屏意图、画中画与前台服务；提供小米/vivo/OPPO/华为权限引导。

**验收标准：** 建立呼叫 P95 不高于 5 秒；双方最终状态一致；悬浮窗计时不中断；挂断、超时、失败均三秒内清理页面与通知。

### 3. 媒体、文件、语音与收藏

**用户期望：** 相册可分页预览、滑动多选并保留完整相册选择状态；图片堆叠可左右切换和展开；视频有封面且播放流畅；语音可倍速、转写和收起；文件可分类预览；收藏详情不显示 JSON。

**具体措施：**

- 统一媒体模型，区分图片、GIF、动态照片、视频、语音、音频、文档和普通文件。
- 大文件使用分片与断点续传，生成缩略图和视频封面；上传前读取服务端限制并显示明确进度。
- 自建相册和文件选择器采用分页、缩略图缓存、滑动多选、预览返回状态恢复。
- 收藏按来源类型渲染专用详情卡；支持快照查看与跳转原位置两条路径，内部复制不暴露服务器 URL。
- 语音转写采用离线优先、在线增强，支持中英混合并明确失败降级。

**验收标准：** 多媒体上传成功率不低于 99%；无 413 HTML 错误泄漏；关闭选择器才清空选择；所有详情均为类型化 UI。

### 4. 资料卡、权限与隐私

**用户期望：** 聊天左上角进入对应资料卡，右上角进入权限管理；返回只回来源页面且不会资料/权限无限叠层；动态可见范围能从好友列表选择。

**具体措施：**

- 建立统一资料路由和单例导航键，资料卡与权限页最多各保留一层。
- 用户、群聊、聊天室分别使用类型化资料卡，显示备注优先但永不翻译姓名、备注或用户内容。
- 权限模型覆盖勿扰、特别关心、黑名单、添加方式、名片添加、陌生人消息、动态可见范围和群权限。
- “仅指定用户/除指定用户外”使用好友分组与多选列表，搜索只作辅助。

**验收标准：** 所有入口进入正确对象；返回栈无环；无网可查看缓存权限说明但不可误提交更改；服务端复核全部权限。

### 5. 动态、论坛、悬赏与投票

**用户期望：** 生活动态、论坛、悬赏和投票都有清晰分类、富媒体、详情、评论、回复、点赞、收藏、转发、举报和审核；投票真正支持多选；管理动作不是 JSON。

**具体措施：**

- 动态支持九格媒体、附近地点、可见对象、置顶区、两分钟内一次编辑、编辑标记、删除和详情页。
- 论坛支持板块与二级分类申请、标签词典、版主申请、审核、付费章节、富媒体评论和管理排序。
- 悬赏支持分类、图片/视频/音频/文件、奖励类型和最长一个月的日期选择器。
- 投票统一单选/多选、图片选项、有效期、结果可见策略、评论和通知模型。
- 1/2/3 管理动作全部通过表单、确认卡和审计记录完成，不向用户显示原始 JSON。

**验收标准：** CRUD、审核和举报闭环；权限矩阵通过；空评论不显示“近期评论多”等错误标签；多选投票有并发测试。

### 6. 资源、商店、余额商店与投稿安全

**用户期望：** 资源下分应用商店和源码商城；商店与余额商店各自独立；用户可在权限允许时投稿，管理端可审核、追踪和封禁。

**具体措施：**

- APK/IPA/HAP 投稿提取图标、名称、包名、版本、大小和权限；源码识别语言、框架和平台，结果可人工校正。
- 建立唯一分类字典和同义词映射，避免同义分类重复。
- 文件进入隔离区，执行哈希、签名、恶意样本、压缩包递归和依赖风险检查后再审核发布。
- 商店实现分类、搜索、商品详情、库存、购买资料、评论/回复和订单状态；余额商店只使用平台余额。

**验收标准：** 危险投稿不能进入公开下载；每次审核和封禁可追踪；库存与订单并发一致；分类唯一。

### 7. 红包、转账、礼物、订单与奖励

**用户期望：** 红包可自己领取，支持按份与随机抢、指定范围和运气王；私发接收人可退回给发送者，群发/活动红包不能由普通接收人退回；24 小时自动退款；订单和资金明细可追踪。

**具体措施：**

- 使用不可变双重记账账本，所有领取、退回、过期、退款采用事务和幂等键。
- 随机红包以分为整数单位分配，最低 0.01，金额守恒且不超领。
- 订单由购买行为自动生成，覆盖商店、余额商店、资源、付费帖子、会员和权益。
- 奖励规则支持注册、登录、签到、邀请、发帖、有效举报等事件，并配置一次、每日次数、奖励类型与额度。

**验收标准：** 高并发下资金守恒；重复请求不重复扣款；24 小时任务可重放；资金、订单、审计三方可对账。

### 8. 全局主题、语言、图标、背景与布局

**用户期望：** 颜色、语言、字体、主题、聊天背景和桌面图标无感全局切换；中文/英语/日语切换完整；状态栏、刘海、键盘和 Dock 全机型适配。

**具体措施：**

- 建立单一 AppearanceStore，通过资源覆盖和 Activity 安全重建广播全局更新。
- 桌面图标只切换 Manifest 中真实存在且通过自动检查的 activity-alias；切换失败自动回滚。
- 默认/全局/单聊背景分层存储，可恢复默认；背景预加载避免闪屏。
- 文案全部使用资源键，加入伪本地化和超长文本截图回归；用户名和用户内容不进入翻译链路。

**验收标准：** 四端关键页面三语言、两主题截图通过；无重启残留、卡字、错位、底部留白或不存在组件崩溃。

### 9. 智能机器人、天气、新闻与语音识别

**用户期望：** 不只回答固定问句，能够理解任意城市天气、逐小时降雨、历史、旅游、文学、科学、人文、地理、农学、哲学、新闻和今日热点。

**具体措施：**

- 将问答拆为意图识别、实体消歧、工具调用、知识检索、生成和来源标注。
- 使用行政区划库和地理编码解析兖州、济宁、曲阜等地点；用户已指定城市时不再强制定位。
- 天气支持逐小时降水起止、预警和数据更新时间；新闻必须查询带时间戳的来源。
- 本地模型负责隐私敏感和离线基础问答，服务器模型负责复杂检索；两者都必须有超时、熔断与降级。

**验收标准：** 固定评测集覆盖城市消歧、天气时段、多学科、实时新闻、无网和失败降级；实时回答附时间与来源。

### 10. 四级管理端与平台治理

**用户期望：** 1/2/3 能进入下级应用和业务对象，查看类型化详情、执行授权范围内的管理、审核和系统发言；4 保持清晰的用户体验。

**具体措施：**

- 统一 RBAC/ABAC 权限服务，前端显示与后端授权来自同一策略源。
- 管理系统按应用、用户、内容、聊天、论坛、悬赏、资源、商店、订单、资金、文件、通知、更新、维护等领域组织。
- 管理员代入查看保留审计上下文，系统发言使用显式标识；匿名内容对管理审计可追溯但禁止越权扩散。
- 所有变更记录操作者、原因、前后值、时间、设备和关联业务。

**验收标准：** 越权测试全通过；批量管理可撤销或冲正；审计不可被普通管理员删除；界面无裸数据结构。

### 11. 定位、地图与二维码

**用户期望：** 软件内地图可查看自己和对方的位置、距离与地点名称，可拖动选点并选择高德、百度或腾讯地图；二维码可扫码、相册识别和加好友/群。

**具体措施：**

- 建立统一地点对象，保存坐标系、名称、地址、精度与时间，并在不同地图坐标系间正确转换。
- 地图页原生呈现双方标记、距离、隐私提示和外部地图路由，不使用伪网页地图。
- 扫码页固定竖屏，明确返回和超时，支持相册选图、个人 UID、群 UID 和业务对象路由。

**验收标准：** 三家地图坐标误差在可接受范围；拒绝定位权限时仍可手动选点；无无限加载；二维码类型不串线。

## 用户未明确提出但必须补充

### 安全与隐私

- 轮换曾暴露的服务器、面板、SSH、数据库和 API 凭据，并使用密钥管理与最小权限。
- 生产 APK 使用固定签名，记录证书指纹，严禁公开 debug 包。
- 增加数据导出、删除、保留期限、隐私授权记录、敏感数据加密与远程注销。
- 管理员查看聊天和真实匿名身份必须有合法业务依据、告知策略和不可篡改审计。

### 数据库与发布安全

- 所有表结构变更使用有版本的迁移，发布前自动备份并演练恢复。
- 为发布增加灰度、暂停、回滚、防降级和公网下载后复算校验和。
- 更新接口签名并防重放；客户端验证包名、版本、签名和哈希后再调起安装。

### 可观测性与性能

- 建立崩溃、ANR、请求耗时、消息延迟、上传成功率、通话质量和数据库慢查询指标。
- 为启动、首页切换、列表滚动、媒体预览和底部弹层设置性能预算。
- 使用分页、差量更新、对象复用、缩略图缓存和后台转码，禁止在主线程解析大 JSON 或生成封面。

### 质量保障

- 建立 Android 品牌/版本/屏幕/字体矩阵和自动截图回归。
- 为历史堆栈中的每个崩溃建立回归测试，包含 Fragment 生命周期、布局参数类型、Glide 销毁期、索引越界和组件别名。
- API 使用 OpenAPI 契约和生成模型，禁止成功响应返回 HTML，错误响应统一错误码与用户可读文案。
- 建立备份、灾难恢复、限流、反滥用、内容安全、账号风控和申诉流程。

## 发布门禁

在进入下一正式版本前，必须同时满足：

1. 四端单元测试、Lint、构建、签名和 APK 元数据校验通过。
2. 下载站测试、发布元数据、APK 哈希和公网下载复核一致。
3. PHP 语法、数据库迁移、备份恢复和核心 API 契约测试通过。
4. 凭据扫描无真实口令、私钥、生产数据和签名材料。
5. 小米、vivo、OPPO、华为和原生 Android 的关键流程真机验收完成。
6. 资金、权限、匿名审计、文件上传和更新链路完成安全评审。
