# 后续开发路线图

本路线图从当前 `2.7.8` 基线继续演进。排序依据是用户数据与资金安全、稳定性和可验证性，而不是页面数量。每个阶段都要求客户端、服务端、数据库、真机和发布链路形成闭环。本轮专项证据见 [2.7.8 发布说明](releases/2.7.8.md)，十一领域的完整目标、逐项状态与验收标准见[全量需求与实施总纲](MASTER_REQUIREMENTS_AND_IMPLEMENTATION_PLAN.md)。

## 阶段 0：建立可信发布基线

**目标：先证明

- 轮换历史暴露的面板、SSH、数据库和 API 凭据，改用密钥登录和密钥管理。
- 固化 release 签名，记录证书指纹，禁止公开 debug APK。
- 统一 `version.properties`、APK Manifest、更新接口、下载站与发布清单版本号。
- 持续执行 `2.7.3` 建立并由 `2.7.4`、`2.7.5`、`2.7.6` 延续的 APK 包名、包内版本、签名、体积和 SHA-256 一致性校验。
- 建立可重复构建、制品校验、签名验证、升级安装和回滚演练。
- 为数据库迁移增加版本号、备份、恢复测试和回滚说明。
- 为四端建立最小冒烟测试，所有历史崩溃加入回归集。

**完成标准：** 四端 release 包可安装升级；公网下载复算哈希一致；凭据扫描通过；数据库可从备份恢复；发布清单可追溯到提交。

## 阶段 1：消息可靠性与离线体验

- 用 WebSocket 或等价长连接承载实时消息，HTTP 轮询仅作降级。
- 为消息增加客户端临时 ID、服务端消息 ID、幂等键、递增游标、发送状态和重试队列。
- 明确发送中、已送达、已读、失败、撤回、本地删除等状态，不混用语义。
- 新消息到达时保持用户当前阅读位置；通过“新消息（N）”锚点回到底部。
- 私聊、群聊、聊天室、客服使用统一消息模型，同时保留各自权限和业务差异。
- 建立账号隔离的本地数据库，缓存会话、资料、消息索引和必要媒体元数据。
- 支持按时间、发送人、标签、文件、链接、媒体和消息类型查询。
- 转发聊天记录使用只读快照和嵌套结构，匿名策略逐层生效，管理角色保留合规审计能力。

**验收指标：** 消息确认 P95 不高于 800 ms；弱网重复消息率接近 0；离线可读；滚动位置回归测试通过。

## 阶段 2：通话、通知与后台能力

- 将呼叫状态定义为服务端权威状态机：创建、振铃、接听、连接、占线、超时、挂断、回收。
- 信令携带会话版本和事件序号，解决重复 offer/answer、双方状态分裂及残留通知。
- 完善 STUN/TURN 健康检查、区域选择、弱网重连和质量自适应。
- 视频默认合理分辨率与帧率，依据网络动态调整；不把 1080p/120fps 作为所有设备的固定目标。
- 正确处理前后摄像头镜像、大小窗交换、画中画计时和沉浸式控制。
- 来电只使用一个高优先级通知渠道，提供接听/挂断动作，结束后三秒可靠清理。
- 按 Android 和各厂商规范提供通知、全屏意图、画中画、悬浮窗、电池优化与自启动引导。
- 系统通话占线时只关闭占线方麦克风，并向双方同步可读状态。

**验收指标：** 呼叫建立 P95 不高于 5 秒；挂断状态最终一致；通知清理 100%；覆盖至少小米、vivo、OPPO、华为和原生 Android 真机矩阵。

## 阶段 3：媒体、文件与缓存管线

- 大文件采用分片、断点续传、限速和可恢复重试，客户端先读取服务端限制。
- 原图/原视频与压缩版本分开管理，保存尺寸、时长、方向、封面、校验和和 MIME 类型。
- 图片、GIF、拍摄动态照片、视频、语音、音频、文档和普通文件保持独立语义。
- 相册和文件选择器采用分页加载、缩略图缓存、选择状态持久化和滑动多选。
- 统一聊天、论坛、悬赏、动态、收藏中的预览器；内部转发不暴露服务端 URL。
- 文件以内容哈希去重，上传前后做恶意文件检测、压缩包递归检查和隔离审核。
- 明确本地缓存上限、按类型/会话/时间清理、下载目录、加密和账号退出清理策略。
- 生成视频封面并提供流式播放、倍速、全屏、进度、亮度和音量控制。

**验收指标：** 媒体上传成功率不低于 99%；超限提示准确；缓存可控；恶意样本不会进入公开下载。

## 阶段 4：资金、红包、订单与权益

- 建立不可变双重记账账本，余额由流水汇总或受控快照计算，禁止直接改余额代替交易。
- 红包明确按份、随机抢、指定范围、公开范围、自己可领、过期退回和运气王规则。
- 私发红包/转账由接收人领取或退回；群发和活动红包按规则处理，管理操作必须留痕。
- 使用数据库事务、行锁或等价并发控制，确保不超领、不重复领取、不重复退款。
- 订单由购买自动生成，涵盖商店、余额商店、资源、付费帖子、会员和权益。
- 商品、库存、价格、优惠、支付、退款、交付和售后拥有独立状态机和审计事件。
- 定时任务处理 24 小时过期、剩余退回和状态更新，任务必须幂等且可重放。
- 每日自动对账，异常进入人工处理队列；所有管理纠正采用冲正记录。

**验收指标：** 并发压测资金守恒；重复请求不重复扣款；账本与业务订单每日 100% 对平。

## 阶段 5：社区、资源与平台治理

- 统一生活动态、论坛、悬赏、投票、资源、商店的分类、二级分类、标签、搜索和审核模型。
- 动态支持九格媒体、地点、可见范围、置顶、两分钟一次编辑、编辑标记、评论、回复、点赞、收藏和转发。
- 论坛支持板块申请、版主申请、付费章节、附件、富媒体评论、置顶/加精/锁定和热度排序。
- 投票支持单选/多选、图片选项、结果可见策略、有效期、评论和管理审核。
- 应用商店与源码商城分域投稿，自动提取包信息或语言信息，但自动识别结果必须允许校正。
- 建立投稿扫描、审核、拒绝原因、申诉、封禁账号/设备/IP及审计记录。
- 1、2、3、4 四级角色使用同一业务对象和权限服务；管理端不直接展示 JSON。
- 所有资料、权限、好友、群聊和内容详情使用类型化页面，返回逻辑禁止无限互相叠加。

**验收指标：** 权限矩阵自动化覆盖；所有管理动作有操作者、时间、原因和变更前后值；用户界面无原始 JSON。

## 阶段 6：全局设计系统与国际化

- 建立统一颜色、字体、间距、圆角、阴影、毛玻璃、按钮、底部弹层和安全区组件。
- 禁止覆盖 Material 背景后再调用 Shape API；底部主按钮在所有设备上保留完整圆角。
- 统一状态栏、刘海、导航栏、键盘与底部 Dock 的 WindowInsets 处理。
- 全局主题、主色、字体、聊天背景和桌面图标通过单一状态源更新，并验证 Activity 重建。
- 中文、英语、日语全部使用资源键；用户姓名、备注和用户内容永不自动翻译。
- 增加伪本地化、超长文本、字体放大、深浅色、TalkBack 和触控范围测试。
- 页面切换、媒体堆叠、大小窗交换只使用可中断、可降级的轻量动效。

**验收指标：** 关键页面截图回归覆盖三种语言、两种主题和主流屏幕；无卡字、遮挡、错位或底部留白异常。

## 阶段 7：智能机器人、天气、新闻与语音识别

- 将问答拆为意图识别、实体解析、工具调用、知识检索、答案生成和来源展示。
- 地名通过标准行政区划和地理编码消歧，不把兖州、济宁、曲阜等不同地点混为一处。
- 天气工具支持当前、逐小时、降雨起止、预警和多城市查询；缺少定位时仍可按用户给出的城市查询。
- 新闻和热点必须使用有时间戳的可靠来源，不用静态知识冒充今日信息。
- 历史、旅游、文学、科学、人文、文化、地理、农学和哲学通过可更新知识库与检索增强，不依赖有限硬编码问答。
- 离线语音识别支持中文、英语及混合语音；在线服务作为可选增强并提供隐私说明。
- 建立固定评测集：城市消歧、天气时点、事实问答、拒答、工具失败、无网降级和多语言。
- 每个回答标识数据时间、来源或“不确定”，避免编造实时事实。

**验收指标：** 工具调用正确率、事实准确率和失败降级达到发布门槛；天气/新闻回答可追溯到时间与来源。

## 用户未明确提出但必须补充的方向

### 安全与隐私

- 敏感数据静态加密、传输加密、证书校验、密钥轮换与最小权限。
- 隐私清单、授权记录、数据导出/删除、保留期限和远程注销。
- 登录设备管理、风险登录、一次性 PIN、恢复码和高风险操作二次确认。
- 内容举报的证据保全、申诉与误封恢复；管理员查看聊天必须有合法依据和审计。

### 工程质量

- 将 API 契约统一为 OpenAPI，生成客户端模型，避免字段漂移和“HTML 代替 JSON”。
- 建立单元、集成、UI、截图、性能、弱网、并发、迁移和安全测试分层。
- 使用 feature flag、灰度发布、崩溃熔断和服务端回滚，避免一次更新影响全部用户。
- 生成 SBOM、锁定依赖、扫描漏洞，并保存构建来源和制品证明。

### 运维与可观测性

- 统一请求 ID、消息 ID、订单 ID 和通话 ID，日志全链路关联且默认脱敏。
- 建立崩溃、ANR、慢帧、消息延迟、推送到达、通话质量、上传失败和对账告警。
- 定义数据库和对象存储的 RPO/RTO，执行跨机备份、恢复演练与容量预警。
- 为 AI、媒体转码、TURN 和推送建立成本配额与异常用量保护。

## 建议质量门槛

- Crash-free sessions 不低于 99.9%。
- 冷启动 P50 不高于 1.5 秒，P95 不高于 3 秒。
- 慢帧占比低于 5%，关键交互无明显主线程阻塞。
- 消息确认 P95 不高于 800 ms，通知到达 P95 不高于 10 秒。
- 媒体上传成功率不低于 99%，失败可恢复。
- 通话建立 P95 不高于 5 秒，双方终态一致率 100%。
- 资金对账一致率 100%，任何差异均阻断结算。

## 统一完成定义

一项功能只有同时满足以下条件才标记为完成：

1. 需求、权限和异常路径清楚。
2. 客户端、API、数据库及后台闭环。
3. 无原始 JSON、敏感链接或技术错误直接暴露给用户。
4. 自动化测试覆盖关键路径与历史回归。
5. Android 目标设备和弱网环境验收通过。
6. 性能、安全、隐私和可访问性达到门槛。
7. 发布、监控、告警、回滚和文档齐备。
