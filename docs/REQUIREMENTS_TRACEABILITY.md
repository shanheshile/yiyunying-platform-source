# 需求追踪

> 完整需求编号、角色范围、实施措施、优先级和统一完成定义以 [全量需求与实施总纲](MASTER_REQUIREMENTS_AND_IMPLEMENTATION_PLAN.md) 为准。本页保留为紧凑能力索引，不再单独承担

本文把长期需求按可核验能力归类。状态含义如下：

- **源码入口可见**：存在页面、接口或主要代码入口，不代表生产闭环。
- **构建可核验**：可以通过本地构建、静态检查或自动化测试证明。
- **需集成验收**：依赖客户端、API、数据库或第三方服务联合验证。
- **需真机验收**：依赖设备、厂商系统、权限、锁屏、后台或网络环境。
- **持续完善**：已有实现基础，但体验、边界、性能或稳定性仍需改进。
- **需求记录**：目标已记录，目前不能声称已经交付。

> 页面或按钮存在不等于功能完成。涉及资金、权限、通话、推送、更新、媒体和隐私的能力，必须有服务端约束、数据库一致性、测试与真实环境验收。

## 验收证据要求

每一行升级为“完成”前，至少要附：

1. 对应源码和接口位置。
2. 数据库迁移及回滚说明。
3. 自动化测试或可重复测试步骤。
4. 目标 Android 设备与弱网验收结果。
5. 服务端权限、异常路径和审计记录。
6. 发布版本、构建产物、签名与 SHA-256。
