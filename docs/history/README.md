# 历史归档说明

## 为什么需要重建历史

当前规范 Git 仓库于 2026-07-30 建立，最早可验证提交是：

```text
c8fe64eeef06e634c84e7c9f7b818f34421a9171 Initial source release 2.7.2
```

在此之前，开发记录主要存在于源码压缩包、交付目录、版本说明、补丁、APK、后端包和文件时间戳中。为了交接和后续维护，本目录将这些材料整理为可审计时间线，但不会把它们伪造成不存在的 Git 提交。

## 证据等级

| 等级 | 含义 | 可以证明什么 |
| --- | --- | --- |
| A | Git 提交、CI 记录、可复现构建和签名发布记录齐全 | 可以定位到源码变更和验证结果 |
| B | 源码/发布归档、版本说明和 SHA-256 较完整 | 可以证明某个快照或交付物存在 |
| C | 仅有构建物、目录名、补丁或文件时间戳 | 只能证明曾出现该批次，不能证明功能完整 |
| D | 需求对话、截图或口头描述 | 只能作为需求来源，不能作为实现证据 |

## 使用规则

1. 需求被写进文档，不代表已经通过端到端验收。
2. “源码中存在入口”不等于“生产环境可用”。
3. 通话、推送、锁屏、后台运行、支付、地图、AI 和语音识别必须在真实服务与目标设备上验证。
4. 资金和权限类功能必须同时具备事务、幂等、审计和异常恢复证据。
5. 任何无法定位来源的 APK 或压缩包都不得作为正式更新包发布。
