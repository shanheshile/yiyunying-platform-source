# 风险登记

本清单同时覆盖已出现的故障、发布风险，以及从项目规模和业务性质推断出的必要工程补强。优先级越高，越应在继续扩展功能前处理。

## P0：发布与数据安全

| 风险 | 影响 | 必须措施 |
| --- | --- | --- |
| 下载站 SHA-256 与本机发布清单不一致 | 用户可能下载到错误或被替换的安装包 | 从受信源码重建、正式签名、复算校验和、原子发布 |
| 历史服务器和数据库凭据曾出现在沟通中 | 主机、数据库和用户数据可能被接管 | 立即轮换凭据、撤销旧会话、检查登录审计、改用密钥和密钥管理服务 |
| debug APK 对外发布 | 调试能力、日志和配置可能泄露 | 仅发布 release 包，验证签名证书及可升级性 |
| 红包、转账、余额、订单缺少不可变账本证明 | 重复扣款、并发超领、余额错账 | 双重记账、幂等键、数据库事务、日终对账、人工冲正而非改历史 |
| 四级角色权限边界复杂 | 越权查看聊天、资料或资金记录 | 服务端强制 RBAC/ABAC、最小权限、操作留痕、越权自动化测试 |
| 数据库迁移与回滚证据不足 | 升级失败或数据不可逆损坏 | 版本化迁移、备份、恢复演练、向前兼容和回滚预案 |

## P1：稳定性与一致性

| 风险 | 已有信号 | 改进方向 |
| --- | --- | --- |
| Activity/Fragment 生命周期竞态 | `onSaveInstanceState` 后提交、Fragment 脱离 Context、销毁后 Glide 加载 | 生命周期感知任务、取消异步回调、幂等导航、严格主线程状态判断 |
| Material 组件背景与 Shape 冲突 | `MaterialButton` 覆盖背景后设置 Shape 崩溃 | 统一主题组件，禁止混用自定义 background 与 Shape API |
| 动态列表索引越界 | 媒体堆叠动画出现极小负索引 | 不可变快照、边界检查、动画结束前校验 adapter position |
| 通话双方状态不一致 | 一方挂断、另一方仍通话；计时为零；重复 offer/answer | 服务端权威通话状态机、单调事件序号、幂等挂断、超时回收 |
| 厂商后台与通知行为不同 | 小米/vivo 等真机表现不一致 | 标准通知渠道、厂商推送、前台服务合规使用、设备矩阵测试 |
| 大媒体上传失败或 413 | 视频和多图发送失败 | 分片上传、断点续传、服务端限额协商、压缩策略、失败重试 |
| 投稿文件存在恶意内容 | APK、源码、压缩包可包含风险载荷 | 隔离存储、哈希去重、杀毒/沙箱扫描、人工审核、下载告警 |
| 离线缓存泄露隐私 | 本地聊天、媒体、资料可被提取 | 数据最小化、加密存储、按账号隔离、退出与远程擦除策略 |
| 国际化不完整或翻译用户名字 | 混合语言、身份字段被错误翻译 | 资源键全量扫描；用户内容永不机器翻译；伪本地化测试 |
| 智能回答把缺数据当结论 | 天气、新闻、地理回答错误 | 工具调用、来源时间、城市消歧、无结果明确说明、离线降级 |

## P2：质量、合规与运营

- **可访问性**：字体放大、对比度、TalkBack、触控目标、横竖屏和刘海区域需要系统化测试。
- **隐私合规**：需要隐私清单、同意记录、数据导出/删除、未成年人策略和保留期限。
- **内容治理**：举报、申诉、审核、封禁、证据保全和误伤恢复必须形成闭环。
- **供应链安全**：生成 SBOM，锁定依赖，扫描已知漏洞，并验证构建来源。
- **可观测性**：建立脱敏日志、崩溃率、消息延迟、通话成功率、上传成功率和资金对账指标。
- **容量与成本**：为媒体、聊天历史、AI、推送和 TURN 建立容量模型、配额、归档和成本预警。
- **灾难恢复**：定义 RPO/RTO，跨机备份，并定期执行恢复演练。
- **接口治理**：以 OpenAPI 或同等契约生成客户端，统一错误码、分页、幂等和兼容策略。

## 已知崩溃回归集

以下历史异常应转成自动化或最小复现测试，不能只做一次性空指针保护：

1. `FragmentManager` 在状态保存后执行回退栈操作。
2. Fragment 已脱离时调用 `requireContext()`。
3. `TextInputLayout` 子项使用错误的 `LayoutParams` 类型。
4. Launcher alias 不存在时切换桌面图标。
5. Activity 销毁后调用 `Glide.with(activity)`。
6. 媒体堆叠动画结束时索引越界。
7. `MaterialButton` 自定义背景后继续调用 ShapeAppearance API。
8. ViewBinding 布局与 Activity 绑定类不一致导致缺失必需 View。

## 风险关闭标准

风险只有在具备可复现用例、修复提交、自动化验证、目标环境验收和发布记录后才可关闭。仅修改界面文字、捕获异常或隐藏错误提示不算关闭风险。
