## 状态口径

仓库采用以下状态描述，避免把界面入口、代码草案或历史记录误写为生产完成：

| 状态 | 含义 |
| --- | --- |
| 源码入口可见 | 能定位到页面、路由、接口或数据结构，但未证明完整闭环 |
| 构建可核验 | 可通过本地构建、静态检查或自动化测试 |
| 需集成验收 | 需要客户端、API、数据库或第三方服务联调 |
| 需真机验收 | 需要 Android 设备、厂商系统、网络或权限环境验证 |
| 持续完善 | 已有实现，但稳定性、性能、可访问性或交互仍需改进 |
| 需求记录 | 已记录目标，尚不能声称实现 |

## 发布阻断项

### P0：历史凭据必须轮换

项目沟通过程中曾暴露服务器、面板、SSH 和数据库凭据。即使当前源码未检出这些明文，也必须视为已泄露并完成轮换；禁止把真实凭据、数据库数据、签名密钥或访问令牌提交到 Git。

### P0：生产默认凭据与会话必须处置

最新只读盘点仍命中 2 个平台账号、1 个管理员、129 个用户、185 枚未过期用户 access token，以及应用 1 的旧演示 secret。源码已补齐停用/删改时的 access+refresh 撤销、refresh 原子轮换和默认凭据审计，但生产处置会强制退出并可能锁住没有已验证恢复渠道的账号，必须由用户明确授权维护窗口与恢复策略后执行。`app_key` 是 APK 内公开的租户唯一 ID，`app_secret` 仅为服务端哈希且当前不参与客户端登录；轮换 secret 不要求重建 APK，不得误改平台 KEY、应用唯一 ID、卡密或 API key。

### P0：正式发布链路尚需证明

正式商用公开下载不得使用 debug APK。当前公开的 2.7.14 仅用于 Debug 安装测试；转正式发布前必须验证 release 构建、签名连续性、升级兼容、回滚策略、强制更新策略和防降级校验。
