# 产品完善与核验清单

更新时间：2026-07-27

本文用于把长期需求拆成可以开发、联调和验收的闭环。状态分为：

- **本版已验证**：代码已进入 2.7.2，并至少通过编译或自动化构建验证。
- **已有能力，需回归**：工程中已有对应入口或实现，但必须继续做真机和前后端回归。
- **待专项完成**：不能仅凭局部代码认定完成，需要继续开发、服务端配置或多设备联调。

## 一、本版已验证

1. 用户端与管理端首页减少常驻页面数量，只缓存当前页与相邻页。
2. 用户端与管理端 Dock 高度收紧，系统手势安全区与 Dock 同色衔接。
3. 管理端功能目录搜索增加防抖和重复查询过滤。
4. 消息列表轮询与首页搜索降低刷新频率，减少主线程重复工作。
5. 2.7.2 四端构建与下载站元数据使用同一发布脚本生成。
6. 2.7.2 下载站静态页面与四个 APK 已同步部署；公网状态、版本号、文件名和文件长度已核验。
7. 下载站部署支持本地与服务器 SHA-256 校验、旧站备份、原子替换和失败回滚。

## 二、消息与聊天

- **已有能力，需回归**：私聊、群聊、聊天室、客服和机器人会话入口；文本、图片、视频、语音、文件、名片、收藏等消息类型；草稿、置顶、置底、隐藏会话、搜索与多选入口。
- **待专项完成**：上翻历史消息时严格保持阅读位置，新消息只显示“新消息（数量）”入口；离线缓存与云端拉取的一致性；消息快照嵌套转发、匿名规则和 1/2/3 真实身份审计；所有消息类型的差异化长按菜单与无障碍触控验证。
- **待专项完成**：聊天左上角按会话类型进入用户、群聊或聊天室资料卡，右上角进入对应权限管理，需覆盖全部入口并做返回栈回归。

## 三、媒体、文件与收藏

- **已有能力，需回归**：相册预览、媒体选择、原图选项、文件选择、媒体预览、收藏分类与详情入口。

## 发布验收原则

1. 客户端、后端、数据库和下载站必须使用同一版本发布单。
2. 每个“完成”项至少要有编译/测试结果；涉及相机、通知、通话、后台、地图和系统权限的功能必须有真机记录。
3. 下载站版本号、APK 名称、文件大小和 SHA256 必须从正式构建产物自动生成。
4. 任何接口错误都转换成用户可理解的中文页面或提示，不直接展示 JSON、PHP Warning、HTML 错误页或服务器路径。
5. 未通过联调或回归的功能保持“待专项完成”，不以存在按钮或局部代码视为完成。
